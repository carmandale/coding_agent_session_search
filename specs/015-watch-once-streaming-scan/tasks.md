# Tasks: watch-once streaming scan

Ordered checklist for the implementer. Plan source of truth lives in [`plan.md`](plan.md); spec is [`spec.md`](spec.md). Tasks are grouped under H2 headers — `/codex-implement` chunks at group boundaries for per-chunk Codex validation.

## Group A — Helpers and scratch-root infrastructure

- [ ] T1: Add `src/indexer/scratch_root.rs` (or inline submodule in `src/indexer/mod.rs`) with `ScratchRootGuard` (RAII path wrapper that `Drop`s with `std::fs::remove_dir_all`), `build_scratch_root(batch: &[DiscoveredSourceFile], workdir: &Path, original_sessions_root: &Path) -> Result<(ScratchRootGuard, Vec<ScratchBuildSkip>)>`, and `derive_pi_sessions_root(scan_root: &Path) -> PathBuf` (FAD-equivalent: if `scan_root/sessions` exists return that, else return `scan_root` — handles both `--watch-once ~/.pi/agent` and `--watch-once ~/.pi/agent/sessions`). Builder strips each source file's `original_sessions_root` prefix and recreates the relative subtree under `<scratch>/sessions/<rel>`. Hardlink first via `std::fs::hard_link`; on `EXDEV` fall back to `std::fs::copy` (APFS clonefile on macOS). On per-file non-EXDEV failure (missing source, permission, etc.), record a `ScratchBuildSkip { source_path, error_message }` and continue with the rest of the batch (Codex-review Round 1 finding — scratch-build failures must NOT abort the run; they're skip records). Only systemic errors (workdir creation failure, scratch root permission issues) propagate. Default `workdir = <data_dir>/scratch/watch-once-streaming/`. Use `uuid::Uuid::new_v4()` for the per-batch subdir name.
- [ ] T2: Add `remap_source_path(conv: &mut NormalizedConversation, scratch_sessions_root: &Path, original_sessions_root: &Path)` that strips `<scratch>/sessions` prefix and rejoins under `<original>/sessions`. No-op if the path doesn't have the scratch_sessions prefix (defensive). Place near the existing per-conversation transform helpers in `src/indexer/mod.rs`. **Phase B Round 1 correction**: prior draft had a single-prefix `scratch_root` parameter that would have produced `~/.pi/agent/sessions/sessions/<ws>/<file>` due to the duplicated `sessions` segment. The two-prefix form below is correct.
- [ ] T3: Define `ScanBatchLimits { max_files: usize, max_bytes: u64 }` plus an env-loader that reads `CASS_WATCH_SCAN_BATCH_FILES` (default 50), `CASS_WATCH_SCAN_BATCH_BYTES` (default 64 MB). Plus a `chunk_by_files_and_bytes` helper that yields batches of `DiscoveredSourceFile`, flushing whichever scan limit fires first. Bytes drawn from `DiscoveredSourceFile.size_bytes`. **Phase B Round 1 correction**: dropped the messages-at-scan limit because `DiscoveredSourceFile` carries `size_bytes` per `scan.rs:205-217` but no message count is available pre-scan. Message-count gating lives at the post-scan buffer-flush boundary (T7) where actual `NormalizedConversation.messages.len()` is known; that's a separate knob (`CASS_WATCH_BUFFER_MAX_MESSAGES`, default 8,192).
- [ ] T4: Unit tests for helpers: scratch_root builder copy-fallback path, scratch-build per-file skip path (missing source → emits ScratchBuildSkip, batch continues), remap idempotence + correctness for the `<scratch>/sessions/<ws>/<file> ↔ <original>/sessions/<ws>/<file>` mapping (assert remapped path equals the original input file), `derive_pi_sessions_root` correctness for both `~/.pi/agent` (returns `~/.pi/agent/sessions`) and `~/.pi/agent/sessions` (returns same) input shapes, chunker boundary conditions (empty input, single-large-file batch, exactly-at-limit batch, files limit firing before bytes, bytes limit firing before files).

## Group B — Watch-once streaming branch

- [ ] T5: Inside `src/indexer/mod.rs` `do_index_run` watch-once branch around `:16237-16420`, short-circuit on kind/mode BEFORE calling `discover_source_files`: if `!explicit_watch_once || kind.slug() != "pi_agent"`, take the existing bulk-Vec path unchanged. ONLY THEN call `conn.discover_source_files(&ctx)`; if the result is empty, fall through to the bulk path. The streaming branch fires only when both predicates pass. **Codex-review Round 1 finding**: putting the kind check FIRST avoids making claude/codex/opencode pay for a discovery call they don't need. Add a regression test (T14) that mocks discover_source_files and asserts it is never invoked under bulk-mode dispatch.
- [ ] T6: Streaming branch implementation: enumerate via `conn.discover_source_files(&ctx)?`, derive `original_sessions_root` via `derive_pi_sessions_root(&root.path)` (T1 helper), run `capture_connector_sources_before_parse` ONCE against the original root (NOT under any scratch ctx — preserves raw-mirror manifest identity per `src/indexer/mod.rs:17306-17317`, `src/raw_mirror.rs:844`, `:2000`), then loop the chunker. Inside each iteration: `build_scratch_root` for the batch (capture any returned `ScratchBuildSkip`s into the run's skip list), construct a `ScanContext::with_roots` pointing at `<scratch>`, `conn.scan(&scratch_ctx)?`, drain emitted conversations, remap source_path using `scratch.path().join("sessions")` + `original_sessions_root`, run per-conv transforms, push to flush buffer, flush mid-batch when buffer hits any of (count/bytes/messages) limits, and **MANDATORILY flush at end of each scan batch** (Codex-review Round 1 finding — requirement #1 says working set must be droppable per batch; without end-of-batch flush, conversations carry across batches in the buffer). Scratch dropped at end of iteration via RAII.
- [ ] T7: Buffer flush function: takes `&mut Vec<NormalizedConversation>` plus counter refs + storage + t_index; calls `ingest_watch_batch_with_oom_split` (preserves PR #233 chunking inside), commits Tantivy, updates `progress.current`, accumulates `ingest_success_conversations`, `quarantined_oom`, `inserted_messages` counters. Storage lock acquired per flush (not per callback), matching existing per-chunk pattern at `:16307-16377`.
- [ ] T8: Wire counter accumulation through `:16380` (connector stats) and `:16415` (`total_indexed`). Per the plan's accounting decisions: stats use `inserted_messages` for the `messages` field (post-persist; matches existing watch-mode semantics at `:16389`); `total_indexed` uses `processed_conversations.sum()` ONLY (already includes single-conv quarantine cases per `:15656`; do NOT add `quarantined_conversations` separately, that would double-count).

## Group C — Run receipt and reconciliation

- [ ] T9: Extend the end-of-`--watch-once` JSON output to include a new TOP-LEVEL key `watch_once_receipt` (Codex-review Round 1 finding — receipt location must be a stable, discoverable JSON contract; top-level avoids burying the new fields under existing `indexing_stats` and keeps existing schema/goldens unchanged). Shape: `{"discovered_files":N, "emitted_source_files":E, "scratch_build_skips":K, "parser_skip_records":N-E-K, "emitted_conversations":C, "ingest_success_conversations":S, "quarantined_oom":Q, "parse_unaccounted_files":0, "ingest_unaccounted_conversations":0}`. Three disjoint terminal file buckets: `emitted_source_files + scratch_build_skips + parser_skip_records = discovered_files`. Both `*_unaccounted_*` fields MUST be 0. Update response schema at `src/lib.rs:70961+` (or wherever the index command's response schema is declared) and any associated goldens/insta snapshots.
- [ ] T9a: Record skipped paths explicitly. At end of run, compute three disjoint terminal sets:
  - `scratch_skipped_paths` = set of `source_path` from accumulated `ScratchBuildSkip`s
  - `parser_skipped_paths = discovered_source_paths - emitted_source_paths - scratch_skipped_paths` (Codex-review Round 3 — the three buckets must be disjoint; prior formula counted scratch skips as parser skips too)
  - `emitted_source_paths` collected from callback
  
  Write to `<data_dir>/quarantine/watch_ingest_poison.jsonl`:
  1. For each path in `scratch_skipped_paths`: `{"source_path":"...", "reason":"scratch_build_failure", "io_error":"<errno text>", "agent":"pi_agent", "timestamp_ms":...}`.
  2. For each path in `parser_skipped_paths`: `{"source_path":"...", "reason":"parser_skip", "agent":"pi_agent", "timestamp_ms":...}`.
  
  The existing OOM-quarantine code at `src/indexer/mod.rs:15717` continues to write `reason: "ingest_oom"` for single-conv OOMs; all three reason values share the same file. Spec 015 Acceptance #1 requires this explicit per-path record, not just the aggregate count in the receipt.
- [ ] T10: Add assertion on `parse_unaccounted_files == 0 && ingest_unaccounted_conversations == 0` at run completion. On failure, write a structured warning to stderr; the per-path records from T9a already cover the spec.md:55 contract for normal skips.
